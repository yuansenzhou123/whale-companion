# 群聊、私聊与机器人自身发言的共同记忆（v2）

共同记忆保留实际聊天中的各方原话及机器人当时生成的回复，不再只索引主人本人。每条带发言角色、说话人、原会话和原时间。旧机器人回复是“当时说过这句话”的证据；不代表其中描述的现实经历真的发生，也不把旧语气当成新的人设示例。

原始会话仍按会话存在 data/store.json。持续更新的本地索引为 data/shared-memory.json（version 2）。启动时把现存记录和v1索引关联进来，之后用户消息与机器人回复都在写入存档时同步索引，不额外向模型批量发送历史。每会话最多保留2000条，总计最多20000条，模型每次按问题检索最多16条相关发言并带上相邻问答，记忆正文有大小限制。

在已认证主人的微信私聊里，可以回顾机器人与其他好友、群聊中的相关对话。群里只读取该群更早的记录、这位主人的相关本人信息及适用的表达要求；不会把其他好友的私人聊天发到群里。其他人也不能因改成同名而读取主人的私人记忆。

当前聊天仍是主要上下文。需要回忆当前会话早期内容时，也能检索已超出普通上下文窗口的片段。其他会话、当前会话更早片段分别标明。查询提到某人时会按发言者和会话线索检索；本人明确确认过的多种称呼可用于理解旧记录中的提及对象，但昵称绝不替代微信身份认证。含糊指代可利用本轮最近几句作为检索线索。

检索带回相关发言的前后问答，因此能区分“别人当时问了什么”和“机器人当时回了什么”。已有自身原话时，不得无依据否认。截图里的“本人/对方”只表示截图左右位置，不能默认“本人”就是当前发图者。

遗忘标记、按来源重置继续保留，密码和密钥等凭据不索引。已明确让忘掉的内容，不因重启回扫而恢复。当前实现按文字、人物、称呼和前后文线索检索，不能保证无限期记住所有内容或每次都命中。原始存档中已经不存在、且旧索引也没有保存的内容不能凭空恢复。

可以通过 /api/memory/status 查看实际索引版本、数量和自身回复数量。实际模型请求日志只记录本轮带入的记忆片段数、来源数、自身回复数、其他发言者片段数，不记录记忆正文或Key；以此检查“记录存在但没有送进模型”的情况。


## 当前跨会话回应要求

已认证主人在微信私聊中提出的、针对明确联系人的回应要求，现在会单独同步到对应账号的下一轮私聊，不依赖历史关键词检索。礼貌的条件句也能生效，无须添加“记住”或“长期”等措辞。每轮已认证主人的当前文字私聊都交给同一聊天模型做语义判断，不用句式或关键词决定是否进入理解，也不再用正则直接生成要求。判断输入只有本轮原话、必要的联系人标识和已经确认的有效要求，不额外附带聊天历史；可承接已有要求做修改或撤销，普通闲聊返回无变更并继续正常聊天。模型识别出修改时只替换对应要求。对象有歧义时先澄清。同名昵称不能代替微信账号身份验证。

目标会话若在理解完成前来信，会等本轮同步完成再回应。模型收到的是该联系人适用的主人要求、已验证的对象身份和当前来信，不会得到主人的整段私聊。间接转述按机器人自己的第一人称表达。主人可在私聊里撤销；明确限今天的要求到期失效。普通归档中的旧指令不会因升级或重启自动重新执行。

该补丁同时适用于 v2 和 v3。v2 只开启回应要求同步，不开启自主朋友圈。状态保存在本地 data/agent-state.json，不纳入 Git；配对的管理页面可通过 /api/companion/context 读取 v2 状态。

语义判断通常比普通回复多一次模型调用，会增加等待和用量。只有模型判断与本轮原话有明确依据时才保存；判断失败保留原状态，不伪称已记住。实际动作仍限当前已实现的能力，不因模型理解一句话就获得任意系统权限。


## 私聊的近期承接与重发

普通聊天依然使用该会话配置的历史窗口，包含用户和机器人的完整最近问答。私聊防复读只针对当前输入的直接复读，不再把较早用户原话或机器人上一轮内容自动当作必须禁止的输出；重发、复述和重新分条可自然承接旧内容。群聊原有防复读规则保留。

可爱风格私聊的短回复中，普通换行和空行都会作为多条微信消息的分隔（含 LF、CRLF 和 CR），受 maxBubbles 和每条长度限制；长正文仍遵守原有分段上限。代码块不按此规则拆开，超过数量的段落合并到最后一个气泡，避免丢失正文。短句整理不再仅因换行就重写。完整自定义人设正文和配置的上下文条数均未改变。本次没有把额外历史发给意图识别分支，也没有增加真实历史的外发范围。

修正单换行漏拆：微信桥接已按 HTTP 回包的 bubbles 数组逐条调用发送；此次让普通换行也在后端生成多个数组元素，而非仅改变同一条消息的显示换行。以本地模拟微信入站的 HTTP 测试验证回包，不向真实联系人发测试消息。
