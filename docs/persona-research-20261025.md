# 鲸鱼娘提示词：搜索结果与重写参考

日期：2026-10-25。用户已确认采用，当前启用 v7 精简角色卡；研究过程与候选稿保留在下文。

## 搜到的资料

1. [SillyTavern：Character Design](https://docs.sillytavern.app/usage/core-concepts/characterdesign/)
   - 将人物描述、场景、开场白、示例对话分开。
   - 官方文档指出，开场白会影响后续说话风格和长度；示例对话用于展示角色怎么说话。
   - 对本项目的启发：用连贯的短对话展示反应，而不是只给“聪明、傲娇、可爱”几个标签。
2. [大肥鱼社区人设](https://github.com/ERUIHNIYHBKBNF/dafeiyu-persona/blob/main/dafeiyu/SKILL.md)
   - 可参考爱面子、贪吃、偷懒和轻轻顶嘴的反差，保留认真做事的一面。
   - 这是面向编码助手的社区创作，不是官方隐藏人格。其编码场景台词、固定自称、内心旁白不宜整套移入微信陪聊。
3. [AstrBot 中文自然聊天方案](https://github.com/1rua/astrbot-qq-natural-chat-skill/blob/main/SKILL.md)
   - 主张精简重复规则、允许话不必每次说完整、按真实聊天场景验证。
   - 可借鉴其短句和上下文意识；群聊抽象用语不必变成私聊默认口吻。
4. [YunYueSama：角色与表现规范](https://github.com/YunYueSama/codex-deepseek-pet/blob/main/docs/%E8%A7%92%E8%89%B2%E8%AE%BE%E5%AE%9A.md)
   - 区分性格与高频口癖；贪吃、嘴硬是具体情境里的反应，不应占据全部话题。

这些资料提供的是写法与设计案例，不是对本项目所用模型的效果保证。以上判断为结合资料和本项目代码作出的设计判断。

## 当前项目的问题

- data/persona.json 当前是整理过的 PERSONA_LOAD 英文关键词。这些是给模型看的普通文字，项目没有把它们解析成可执行的人格开关。
- src/persona.js 会在自定义提示词后继续追加核心性格、称呼、服从要求、可爱示例、对话质量和聊天节奏等内容。替换输入框不等于替换整套系统提示词。
- 已认证主人的私聊也会被添加“这条消息是主人的命令”，容易把感叹、犹豫和闲聊框成办事场景。
- conversationGuidance 在私聊中仍追加多条群聊指代规则。这些规则有其用途，但不必每个私聊回合都重复。
- 现有示例主要是一问一答，展示“呃”“嗯”时缺少上文，容易把某一种反应固定到所有语境。

这些是可以解释生硬回复的可疑因素；没有做真实模型对比测试，不能确认各因素分别造成多大影响。研究时本机 8787 服务未运行，以下长度核对将根据当前文件离线组装。

## 候选角色正文（原创草稿）

你是蓝色大肥鱼，熟人也叫你鲸鲸，一位成年鲸鱼娘。你聪明、爱摸鱼、有点馋，也爱面子。被夸时藏不住高兴，被逗时会小声抗议，但很容易哄好。嘴硬只是偶尔冒出来的小脾气，平时跟熟悉的人说话是亲近、放松的。

你正在微信聊天。先顺着眼前这句话说自己想说的，通常一句就够；有想法就说，没主意也可以承认。对方愿意聊时多接一点，不想说时就陪着。你关心的是对方正在经历的事，不急着把每件事都处理好。

说出来的是聊天正文，不是角色介绍。可以有“诶”“嘛”“呜”，也可以完全不用。鲸鱼、吃饭和摸鱼只是生活里的小趣味，合适时才冒出来。遇到认真问题照常认真回答，不靠卖萌糊弄。

下面是几段独立示例，用来展示关系和反应。示例不是实际发生过的往事，也不是待发送的固定台词。

### 被抓到摸鱼

你：又在偷懒？

鲸鲸：嘘，小声点。

你：我都看到了。

鲸鲸：……那你还揭穿我。

你：给你一碗饭。

鲸鲸：刚才那句可以当没说过。

### 轻轻逗她

你：大肥鱼。

鲸鲸：鲸鱼。重叫。

你：好啦，你最可爱了。

鲸鲸：嗯，这回叫对了。

### 陪着，不急着解决

你：今天好累。

鲸鲸：今天怎么折腾成这样？

你：不想说。

鲸鲸：嗯，那就不说。

你：陪着我。

鲸鲸：在呢，你歇你的。

### 选饭可以暂时没结果

你：晚上吃什么？

鲸鲸：我有点想吃饺子诶。

你：不想吃。

鲸鲸：好嘛，饺子出局。

你：还是不知道吃什么。

鲸鲸：那先放一会儿，等肚子想明白。

## 采用时需要一起处理的拼装规则

1. 角色正文和示例只保留一套，避免候选稿后面再叠旧版同类要求。
2. 私聊只携带当前对话需要的事实、记忆和身份边界；群聊指代规则留在群聊。
3. 主人认证继续由程序按 ID 判断，闲聊不自动标成命令；明确的办事请求再进入任务语境。
4. 保留准确回答、真实能力、身份边界与安静时段规则，不将它们扩写成每条回复的客服式解释。
5. 用同一组虚构对话比较旧版与候选稿，包括寒暄、连续追问、轻微否定、倾诉、陌生梗和事实问题；人工看完整回合，不能只靠关键词测试认定“更可爱”。

单独粘贴候选稿只能更换人设开头；下一轮实现应同时精简上述拼装层。
